# Qt 6 for WebAssembly build experiment (VPS, 2026-10-25)

Result: **SUCCESS.** Multi-threaded Qt 6.13.0 (dev) for wasm-emscripten builds with qtbase, qtshadertools,
qtdeclarative and qtsvg, and a minimal Qt Quick app links to .wasm/.js. The single-threaded fallback was not needed.

## Versions
- Qt source: ~/src/bun-ui/upstream/qt/qt5 @ a7a102f8 (dev). Used read-only, out-of-source builds only.
  - qtbase 4d41f83371c1 (v6.12.0-beta1-2857), QT_REPO_MODULE_VERSION 6.13.0
  - qtdeclarative c7b4986dbf6b, qtshadertools 6dd127f975e5, qtsvg e05633e79070
  - Initialized submodules include everything needed; qtlanguageserver is absent (optional, skipped by configure)
- Emscripten 5.0.5 (bc569045b14c), the version pinned by qtbase/cmake/QtPublicWasmToolchainHelpers.cmake
  (QT_EMCC_RECOMMENDED_VERSION "5.0.5"). emsdk @ d7b4130
- Host: Ubuntu, GCC 15.3.0, CMake 4.3.4, Ninja 1.13.2, Python 3.12.15. 12 cores, 45 GB RAM

## Commands
```sh
# 1. emsdk (~4 min, mostly downloads)
cd ~/build/qtwasm && git clone https://github.com/emscripten-core/emsdk
cd emsdk && ./emsdk install 5.0.5 && ./emsdk activate 5.0.5

# 2. Host Qt (script: ~/build/qtwasm/host-build.sh, log: logs/host-build.log)
cd ~/build/qtwasm/host-build
~/src/bun-ui/upstream/qt/qt5/configure -release -prefix ~/build/qtwasm/host \
  -submodules qtbase,qtshadertools,qtdeclarative,qtsvg -nomake tests -nomake examples
ninja -j10 && ninja install

# 3. wasm Qt (script: ~/build/qtwasm/wasm-build.sh thread, log: logs/wasm-thread.log)
source ~/build/qtwasm/emsdk/emsdk_env.sh
cd ~/build/qtwasm/wasm-build
~/src/bun-ui/upstream/qt/qt5/configure -qt-host-path ~/build/qtwasm/host -platform wasm-emscripten \
  -prefix ~/build/qtwasm/wasm -release -feature-thread \
  -submodules qtbase,qtshadertools,qtdeclarative,qtsvg -nomake tests -nomake examples
ninja -j10 && ninja install
# (wasm-build.sh nothread would configure -no-feature-thread into wasm-build-st / wasm-st; not run)

# 4. Hello QML app (source: ~/build/qtwasm/app/hello, log: logs/hello-thread.log)
cd ~/build/qtwasm/app/build-thread
~/build/qtwasm/wasm/bin/qt-cmake -G Ninja -DCMAKE_BUILD_TYPE=Release ../hello && ninja -j10
```

## Failures, warnings and notes
- No build failures. No missing host dependencies: the host configure found ICU, FreeType, HarfBuzz, Fontconfig,
  EGL, desktop OpenGL, Vulkan, xkbcommon, XCB and Wayland (only xcb-sm is missing, which does not matter here).
- Link warning: `-pthread + ALLOW_MEMORY_GROWTH may run non-wasm code slowly` (expected for threaded Qt).
- Threaded builds need cross-origin isolation (COOP: same-origin, COEP: require-corp) to serve.
- Not done: no in-browser run of hello.html (only build and link were proven), no single-threaded build, no
  SIMD/wasm-exceptions variants, no size optimization (-Os/-Oz, wasm-opt, Qt feature trimming).
  Next steps for the emulator port: smoke-run under a COOP/COEP server in headless Chromium, then try
  -feature-wasm-simd128 / -feature-wasm-exceptions and a trimmed feature set to reduce the 20 MiB wasm.
